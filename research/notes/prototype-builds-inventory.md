# Inventory: every prototype/beta build checked so far, and why

A running index so past checks don't get re-done by accident. Per [prototype-leaks.md](prototype-leaks.md):
no filenames, versions, or provenance here — each entry is identified by platform + rough era +
what made it worth checking, which is enough to recognize "yes, we already looked at that one."

| # | Platform | Rough era | Why it was checked | What was found | Verdict |
|---|---|---|---|---|---|
| 1 | Xbox | Debug build, contemporaneous with Burnout 2's release (2003) | Debug builds are typically far less stripped than retail — worth checking for embedded source paths / assert strings | **Jackpot.** `GTASSERT` macros embed `__FILE__` as a literal string, exposing the entire 176-file source tree structure one game before Burnout 3. Found the `CB<N>`/`Toolkits` naming convention here, confirmed `CB3AsyncDataLoader::Update` etc. structurally match Burnout 3 retail almost line-for-line. | **Most valuable source used.** Full writeup: [burnout2-source-tree-map.md](burnout2-source-tree-map.md). 6 of 176 source files swept so far — extending this is still open work (ROADMAP item 3). |
| 2 | Xbox | Pre-release, ~6 weeks before Burnout 3's own retail ship | Same title, same architecture — worth checking whether this specific build carries debug symbols the retail master doesn't | No `GTASSERT`/source-path strings anywhere on the disc (in any of its three executables). String count is comparable to retail, not inflated like a debug build would be. One minor curiosity (a `TESTTESTTEST...` buffer-fill pattern not present in retail) but nothing name-worthy. | **No debug-symbol value.** Same build configuration as retail. Might still be useful for feature/content diffing (what shipped vs. didn't) but that's separate, lower-priority work, not pursued. |
| 3 | Xbox | Online-focused demo build | Different build target (demo, not full retail) — worth checking whether a cut-down build was compiled less aggressively stripped | Contains genuine Xbox Live networking strings (`XOnlineFriendsStartup`, buddy-list handling) not in retail, confirming this demo emphasizes online functionality. No `GTASSERT`/source-path strings — same stripped configuration as retail otherwise. | **No debug-symbol value**, but confirms this demo build's own distinct scope (online features) if that's ever independently useful. |
| 4 | Xbox | Earlier "preview" build, distinctly smaller and structurally different from the other three | Different `default.xbe` size and directory layout (`Vehicles/<class>/` instead of retail's `pveh/<class>/`) from every other build checked — worth confirming whether it predates the folder-naming convention settling | No `GTASSERT`/source-path strings. Fewer total strings than retail (consistent with a smaller, earlier, less-featured build rather than a debug one). Some `.xmv.old`/`.xmv.new` leftover files suggest mid-iteration build artifacts. | **No debug-symbol value.** Archaeological interest only (shows the folder-naming convention changed at some point before retail) — not pursued further. |
| 5 | PlayStation 2 | Pre-alpha, mid-2004 (same production window as the Xbox retail build) | Different platform port of the *same* title and *same* era — different architecture rules out binary structural diffing, but worth checking for linker-level debug artifacts a console SDK might leave in | **Second jackpot, bigger than #1.** Ships linker map files with **fully-qualified, unmangled C++ signatures** (class, method, and truncated argument types) — no demangling needed, unlike anything else checked. One of the four map files present on the disc turned out to describe a different, non-matching link of the game; the correct one (matching the disc's actual boot executable) parses to **4,588 methods across 672 classes**, spot-confirmed structurally against `CB3AsyncDataLoader::Update` (exact algorithm match: same ring-buffer offset, same magic constant, across all three of Xbox retail / Burnout 2's Xbox debug build / this PS2 build). | **Most valuable source overall**, despite the architecture mismatch ruling out automatic binding to Xbox addresses. Full writeup: [ps2-build-symbols.md](ps2-build-symbols.md). A call-graph crawl from known anchors turned 5 seed points into **113 confirmed (class, method) pairs across 44 classes** — see [ps2-xbox-binding.md](ps2-xbox-binding.md) and [research/data/ps2-confirmed-callgraph.csv](../data/ps2-confirmed-callgraph.csv). Binding those PS2 names to *new*, currently-unnamed Xbox addresses needs a manual structural read per function — tried and failed twice so far on physics/AI/vehicle-render targets specifically because the PS2 build leans heavily on VU0 vector-coprocessor instructions for anything math-heavy, which decompiles into something with no visual resemblance to the equivalent x86 code. **Non-vector, control-flow-heavy targets (state machines, managers, UI, flag logic) are the better bet going forward** — that's the shape of function `CB3AsyncDataLoader::Update` happened to be, which is exactly why that one match worked. |

String count comparable to retail. Restricted content confirms it's a public/press demo, not a dev build: only 4 of the full vehicle-class roster present, many localized language variants bundled (more than retail ships). | **No debug-symbol value.** Same stripped configuration as retail; nothing further to check here. |

Burnout 3's own retail binary was checked for the same kind of string and doesn't have any. | **Semantic corroboration, not new names.** Full writeup: [burnout-revenge-xbox-tuning.md](burnout-revenge-xbox-tuning.md). ## What this means practically

- Sources #2, #3, #4, #6 (four separate Xbox prototype/demo builds) are **checked off** — no further
  time should go into re-scanning them for debug symbols. They could still matter for a
  feature/content timeline (what existed at what point before ship) if that ever becomes a goal, but
  that's unrelated to function naming.
- Source #1 (Burnout 2 debug build) still has 170 of 176 source files' worth of unswept
  `GTASSERT` cross-references left — mechanical work, not blocked on anything.
- Source #5 (PS2) is the active frontier: the name inventory (113 done, ~560 more available in the
  672-class list) can keep growing cheaply via the call-graph crawl tooling in
  `research/tools/ghidra-ps2-crawl/`; turning names into actual Xbox atlas entries is the slow part,
  and works best on non-vector-math functions specifically.
